# 더굿모닝치과 — Good Morning Web

## 프로젝트
강도욱 원장님의 사전설문·개편 제안서·디자인 가이드와 제공 사진을 기반으로 만든 Hono + Cloudflare Pages 홈페이지입니다. 차콜·노랑, 실제 공간·의료진 사진, 원본 로고에서 추출한 심볼을 적용했습니다. 헤더의 병원명은 실제 텍스트입니다.

## 원문 중심 콘텐츠 복원 (2026-09-30)
요청: 디자인뿐 아니라 원장님 요청과 워딩을 콘텐츠에도 최대한 반영.

### 반영 범위
- 메인: “환자의 불편함을 한 번 더 듣는 치과”, “치료가 막막했던 순간, 다시 가능성을 이야기합니다”, “어려운 치료에는 신중한 해답을, 불안한 마음에는 믿을 수 있는 설명을” 반영.
- 원안의 **9개 차별점**, **8개 대표 진료 카드**, 5개 핵심 태그 및 **의료진 5인** 노출.
- `/mission`: 1990년 아버지에게 이어받은 개원 이야기, 수면진료를 더한 이유, 더굿모닝 이름의 유래를 1인칭 말투로 복원. 장애인 진료에 대한 원장 메시지 별도 섹션.
- **31개 진료 전체**의 반복 일반 문장을 제거하고, **182개 환자 증상 표현·96개 설명 소섹션·285개 진료 FAQ** 및 진료별 과정·차별점·관련 진료 링크로 구성.
- `/faq`: 일반 내원 FAQ 6개 + 진료 FAQ 285개 = **291개**, 진료별 목차와 상세페이지 연결. 화면과 FAQ JSON-LD가 같은 데이터를 사용.
- 사이트 검색에 진료별 설명·소제목·질문 추가. 기존 URL 유지.
- 실제 공개 전에는 의료진의 의학적 내용·진료 가능 범위·운영 조건 검수가 필요합니다. 제안서 반영은 의료광고 적법성이나 효과를 보증하지 않습니다.

### 원문 / 보완 / 보류의 구분
- 기준 자료: 사용자 제공 Drive의 `9.3_더굿모닝치과_홈페이지_개편제안서.docx`.
- 자료 폴더: https://drive.google.com/drive/folders/1nHFzdlo9_6hEZS-GOhcHdhqbtDYiyHZ9?usp=sharing
- 진료 상세는 제안서 4-2~4-5, 메인은 3-1~3-5, 미션은 6-1 기준. `src/data.ts`의 `sourceLines`는 비공개 추출본 `.sources/proposal.txt`의 대조 구간입니다.
- 285개 진료 질문은 공백 정규화 후 모두 원본에서 확인됩니다. 답변까지 전부 그대로라는 뜻은 아닙니다. 원문의 중복 질문은 정리했습니다.
- 원문이 소제목·제작 지시만 있는 부분은 환자용 설명으로 보완했습니다. 특히 턱관절 FAQ 4개는 질문만 있어 답변을 새로 작성했습니다. 새 설명을 원장 직접 발언처럼 인용하지 않았습니다.
- “인체에 무해”, 기억·무통·식립 정확도 보장, 모든 환자의 당일 완성, 장기 수명 보장, 무조건 대학병원에 가지 않아도 된다는 표현은 수정했습니다.
- 금식·복용 약은 개별 안내, 임의 중단 금지, 진정 중 호흡 위험·보호자·운전 금지를 명시했습니다. 원본의 재채기를 참으라는 안내와 신경치료 후 영양 공급 설명 등 부정확한 표현도 수정했습니다.
- 보험·보증·치료 기간의 확정되지 않은 숫자나 조건은 일률적으로 약속하지 않습니다. `「○」` 같은 빈칸과 제작 메모·링크 지시문은 공개하지 않습니다.
- 개원 연차 “올해로 35년”은 “1990년부터, 2대째”로 수정했습니다.
- 특정 환자의 질환·이사 지역·치료 결과 회고, 환자 사진·후기는 공개하지 않고 원장 철학 부분만 발췌했습니다.
- 일요일 진료는 청량리 본점에 한정하고, 광명 일요일·대체공휴일 휴진을 명시했습니다. 청량리 대체공휴일 일정은 전화 확인으로 안내합니다.
- 기존 D1 게시물 3개는 일반 안내 글로 그대로 두었습니다. 사용자 편집 콘텐츠를 덮어쓰지 않았습니다.

## 데이터와 보안
- `src/data.ts`: 진료·의료진·지점·FAQ·영상·미션. 진료 원고는 `sourceContent` 단일 데이터로 관리합니다.
- `src/glossary.ts`: 용어 데이터. 진료 설명 일부를 연동합니다.
- D1 `posts`: id, slug, title, body, type, status, created_at, updated_at.
- D1 `admin_sessions`: 세션 토큰 SHA-256 해시·8시간 만료.
- D1 `admin_attempts`: 비밀을 섞은 IP 해시·시도 시각. 5회/15분 제한, 다음 요청에서 만료 정보 정리.
- HttpOnly/SameSite 세션, HTTPS Secure, 변경 API Origin 검증, 출력 escape, CSP, 이미지 magic bytes·크기 검사, SVG 차단.
- R2 이미지는 공개 글에 참조된 경우에만 비로그인 접근 가능. 초안 이미지는 관리자만 접근.
- `.dev.vars`의 무작위 ADMIN_PASSWORD는 Git 제외. 운영 환경에 별도 비밀 설정 필요.
- `.sources/`는 비공개 작업 자료로 Git/빌드 제외. 공개 정적 자산에 환자 수술 사진을 넣지 않습니다.
- 지점 선택만 sessionStorage 사용. 환자 회원가입·건강정보 수집 없음.
- Vite `emptyOutDir:true`로 삭제한 자산이 dist에 남지 않게 합니다.

## 정식 오픈 전 남은 작업
1. 의료 문구·실제 진료 범위·의료진 재직/근무 지점·진정 담당 체계·휴일/주차/장애인 접근 최종 검수.
2. 최신 비급여 수가와 적용일 확인 후 법정 고지. 현재 `/pricing`은 확인 안내입니다.
3. 환자 동의·촬영 조건·기간 확인 후 사례 기능과 필요한 인증 도입. 현재 `/cases`는 안내만 제공합니다.
4. 공식 네이버예약·카카오톡·블로그·인블로그 주소 연결. RSS/YouTube 자동 갱신은 미구현.
5. 회원가입·환자 예약 관리·사례 슬라이더·원장별 글 작성자·고급 WYSIWYG·500개 용어·지역 SEO 확장은 미구현.
6. 실제 3D/WebGL·실내 3D 투어는 미구현. 현 연출은 경량 CSS/SVG입니다.
7. 사업자·개인정보 보호책임자·정식 약관·의료광고 심의 필요 여부 확정.
8. 사용자가 배포 경로를 선택한 뒤 운영 D1/R2 설정. Wrangler database_id는 로컬용이며 실제 운영 ID가 아닙니다.
9. 운영 관리자 비밀·마이그레이션·데이터 이관. 로컬 D1/R2는 배포만으로 자동 이전되지 않습니다.
10. 최종 승인 후 PUBLIC_SITE_URL·검색엔진 등록·분석 도구·도메인 전환.
