## 영상 정지 문제 수정 (2026-10-01)
- 재현한 문제: 저장된 모션 OFF/동작 줄이기/Save-Data가 영상 소스 연결뿐 아니라 수동 재생 버튼까지 비활성화했습니다. reduced-motion CSS도 영상을 강제로 투명하게 만들고 있었습니다.
- 자동재생 정책과 명시적 영상 재생을 분리했습니다. 기기/사용자 설정에 따른 자동 다운로드 제한은 유지하되, 영상 위 `영상 재생` 버튼은 항상 조작할 수 있습니다. 직접 재생해도 장식 모션은 OFF를 유지합니다.
- 자동재생 거절/네트워크 오류/연결 지연 때 첫 화면 안에 안내·재생 버튼·새 창 링크를 표시합니다. 재생 성공 시만 안내를 숨기며, 실패한 자동재생을 무한 반복하지 않습니다.
- 클릭/탭 이벤트 안에서 동기적으로 play()를 요청합니다. 이전 비동기 재생 요청의 오류가 최신 재생 상태를 덮어쓰지 않도록 시도 번호를 관리합니다.
- 기기나 전체 모션 설정을 다시 변경하면 직접 재생 허용을 초기화하여 설정을 다시 존중합니다.
- 추가 발견: 미리보기의 `/static/video/*`가 Range 요청을 무시하고 200 전체 응답을 반환했습니다. Safari/iOS 부분 다운로드 호환성을 위해 `/films/clinic-opening.mp4`, `/films/clinic-opening-mobile.mp4` 경로를 추가했습니다.
- `/films/:file`은 위 두 파일만 허용하고 ASSETS에서 가져옵니다. 런타임 파일 시스템/외부 프록시/영구 메모리 저장 없음. 최대 약2.3MB 파일을 요청 단위로 읽어 범위를 반환합니다. 정식 배포 시 ASSETS 바인딩도 확인해야 합니다.
- 206/Content-Range/Accept-Ranges/Content-Length, HEAD, suffix/open range, 416, If-Range 불일치 처리를 구현했습니다. 원본 자산은 public/static/video에 유지하되 브라우저 재생은 새 경로를 사용합니다.
- 모바일 터치로 저장 OFF·reduced-motion·Save-Data·자동재생 거절을 각각 재현한 뒤 실제 시간 증가와 opacity=1 검증. 네트워크 차단 해제 후 재시도도 검증했습니다.
- 원본 바이트와 206 응답의 정확한 일치 및 전체 smoke/typecheck/build 통과. 실제 사용자 기기와 동일한 환경은 아직 확인되지 않았으며, 실제 iOS/인앱 브라우저 검수는 별도 필요합니다.

## 데이터 / 보안
- Hono SSR + TypeScript + Vite, public/static CSS/vanilla JS/자산.
- `src/data.ts`: 진료 sourceContent·의료진·지점·FAQ·영상·미션. `src/glossary.ts`: 용어.
- D1 posts: id, slug, title, body, type, status, created_at, updated_at.
- D1 admin_sessions: SHA-256/8시간. admin_attempts: 비밀 섞은 IP해시, 5회/15분.
- HttpOnly/SameSite, HTTPS Secure, Origin 검증, escape, CSP, magic bytes, SVG 차단.
- R2: 공개 글 참조 이미지만 비로그인 접근, 초안은 관리자 전용.
- `.dev.vars`/`.sources/` Git 및 빌드 제외. sessionStorage는 지점/모션 UI만.
- 회원가입/건강정보 수집 없음. Vite emptyOutDir로 삭제 자산 잔재 방지.
