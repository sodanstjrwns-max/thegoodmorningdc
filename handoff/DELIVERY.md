# 관리자 사용법 — 기본 운영

## 1. 로그인과 안전한 종료

관리자 주소 `/admin`에서 별도 전달받은 비밀번호를 입력합니다. 별도 아이디는 없습니다. 공동 사용 PC에는 비밀번호를 저장하지 말고 작업을 마친 뒤 로그아웃합니다. 로그인 실패가 반복되면 15분 제한이 적용될 수 있습니다. 현재는 역할별 계정이 아닌 단일 관리자 비밀번호 방식입니다.

## 2. 콘텐츠를 바꾸는 기본 순서

1. 해당 탭에서 항목을 찾고 **편집**을 누릅니다.
2. 내용을 수정한 뒤 **초안 저장**을 합니다. 기존 공개본은 바뀌지 않습니다.
3. **미리보기**에서 문구·이미지·관련 링크를 확인합니다.
4. 의료정보·자격·시간·금액과 근거를 확인한 후 **공개**합니다.
5. 로그아웃한 창에서 해당 공개 페이지를 다시 확인합니다.

“다른 창에서 변경되었습니다”가 나오면 덮어쓰기를 반복하지 말고 목록을 새로고침한 뒤 최신 내용을 다시 확인합니다. 저장 중에는 창을 닫거나 다른 항목으로 이동하지 않습니다.

## 3. 자주 쓰는 메뉴

| 관리자 탭 | 할 수 있는 작업 / 주의점 |
|---|---|
| 지점·시간·예약 | 전화·주소·공식 링크·요일별 시간·휴진 예외 수정. 청량리/광명 구분 필수 |
| 진료·진료별 FAQ | 소개·증상·과정·질문/답변 수정. 결과 보장 문구와 확인 안 된 의료주장 금지 |
| 의료진·전체 약력 | 이름·자격·약력·사진 수정. 병원 확인 자료 기준으로 작성 |
| 설명 영상 | 실제 YouTube 영상 ID·분류·제목·표지 수정. 환자 이미지 공개권한 확인 |
| 운영정보·승인 대기 | 수가와 주차·접근성 등 운영정보 관리. 초기43개 비공개 검토자료 일괄 공개 금지 |
| 공식 채널 | 공식 RSS 연결 확인/갱신. 본문은 원문 사이트에서 관리 |

## 4. 수가표 수정 시 꼭 확인

`운영정보·승인 대기`에서 수가 항목을 찾아 수정합니다. **기존32항목은 이미 공개 승인된 상태**이므로 다시 승인 대기로 돌릴 필요가 없습니다. 새 금액은 병원에서 확인한 자료로만 변경합니다. 원본에 없는 적용일을 게시일로 대신 입력하지 않습니다.

수가표 화면을 수정해도 원본 PDF 파일이 자동으로 바뀌는 것은 아닙니다. **금액 변경 시 표와 PDF를 함께 검토**하고, 정적 PDF 교체가 필요하면 기술 담당자가 승인된 파일로 교체·배포합니다.

## 5. 수정 취소와 복원

**변경 이력 → 이 버전으로 초안 편집**은 편집기에 과거 내용을 불러오는 기능입니다. 자동 저장·공개가 아니므로 검토 후 초안 저장/공개가 필요합니다. 기본 콘텐츠의 **원본 복원**과 새 콘텐츠의 **삭제**는 다르며, 관련 진료에 연결된 항목은 삭제가 제한될 수 있습니다.

# 사례·채용·접수 운영

## 치료사례·환자 후기 공개

1. **치료사례·환자 후기** 탭에서 새 항목을 작성합니다.
2. 실제 내용·관련 진료·개인차/부작용/주의사항을 입력합니다.
3. 전후 사례는 전/후 이미지 위치를 선택해 올리고 촬영일·촬영조건·치료기간을 기록합니다.
4. 웹 공개 동의·비식별·의료진 및 광고 검토와 내부 관리번호/담당자/검토일을 확인합니다.
5. 초안→미리보기→공개 후 `/cases`를 확인합니다.

JPG·PNG·WebP 이미지5MB 이하를 사용합니다. 동의 관리번호에 환자 이름을 넣지 말고 동의서·진료기록 자체를 업로드하지 않습니다. 필수 검토와 실제 이미지가 없으면 공개가 차단됩니다. **공개 내림**은 초안·이력을 보존합니다. 다른 공개 콘텐츠가 같은 이미지를 참조하면 그 공개 참조도 별도 확인해야 합니다.

## 채용공고 작성

**채용 공고** 탭에서 직무·지점·고용형태·시간·급여·지원자격·본문·확인 근거를 입력하고 접수 상태·마감일을 설정합니다. 조건 확인 후 공개하고 `/careers`를 확인합니다. 공고가 없어도 별도 인재풀 접수 기능은 존재합니다. 공고 종료와 인재풀 운영 여부를 혼동하지 마세요.

# 정식 오픈은 별도 전환 절차입니다

현재 제작본을 전달해 검수하는 것과 기존 공식 홈페이지를 교체하는 것은 다른 단계입니다. **이 납품 준비에서는 DNS·기존 도메인·인블로그를 변경하지 않습니다.** 담당자와 실행일은 아래 빈칸을 채워 확정합니다.

## 오픈 전 → 전환 → 전환 후

| 단계 | 실행 항목 | 담당 / 승인 |
|---|---|---|
| 1. 병원 확인 | 앞 페이지 사실·수가·의료문구·영어·개인정보 확인 | 병원 지정 / 미정 |
| 2. 운영 준비 | 접수 담당자·확인주기·비밀번호 인수·비용/유지보수 담당 확정 | 병원/계정 담당 / 미정 |
| 3. URL 보존 | 기존 URL 목록·리다이렉트 표·인블로그 라우팅 및 자체 게시판 충돌 해소 | 기술 담당 / 미정 |
| 4. 전환 준비 | 기존 DNS 값·라우팅·앱 버전 보관, 최신 DB/R2 백업, 복구 대상 확인 | 기술 담당 / 미정 |
| 5. 전환 승인 | 전환 일시·영향 범위·중단/롤백 기준 확인 | 최종 승인자 / 미정 |
| 6. 전환 실행 | 승인된 도메인/DNS·라우팅 적용, 정식 PUBLIC_SITE_URL 설정 | 기술 담당 / 미정 |
| 7. 직후 검수 | 주요 경로·예약/전화·수가·영상·접수·관리자·SSL 재검사 | 기술+병원 / 미정 |
| 8. 검색 운영 | 정식 도메인 index/canonical/사이트맵 확인, 검색 도구 등록 | 검색/운영 담당 / 미정 |

## 인블로그 보존 — 가장 먼저 확인

기존 공식 홈페이지의 `/blog/*`와 새 사이트의 자체 `/blog`가 충돌할 수 있습니다. 새 사이트를 기존 도메인에 그대로 연결하면 기존 글이 가려질 수 있습니다. **기존 인블로그 URL의 처리방식과 자체 게시판 경로를 확정하기 전에는 전환하지 않습니다.** 현재 RSS 원문 링크를 연결한 것만으로 도메인 전환 후 경로 보존까지 해결된 것은 아닙니다.

## 문제가 생기면

- **문구·금액 오류**: 공개 콘텐츠 확인 → 관련 항목 초안 수정/공개 또는 사례 공개 내림. 단순 오류에 전체 DB 복구부터 하지 않습니다.
- **광범위한 화면·서버 오류**: 변경 중지 → 직전 배포와 비교 → 검증된 앱 버전으로 되돌리고 기능 재검사.
- **도메인 전환 장애**: 미리 보관한 DNS/라우팅으로 복원 → 기존 홈페이지와 인블로그 접근 확인. 복구 반영시간은 환경에 따라 다릅니다.
- **데이터 문제**: 현재 DB/R2부터 추가 백업 → 쓰기 중단 여부 승인 → 별도 환경 복구 검증 → 승인 후 필요한 범위만 복원. 앱을 되돌려도 DB는 자동으로 되돌아가지 않습니다.

# 백업·담당자 인계와 수령 확인

## 기술 담당자에게 전달할 정보

| 항목 | 기준값 |
|---|---|
| 플랫폼 | 사용자 소유 Cloudflare 계정 · Pages + D1 + R2 |
| Pages 프로젝트 | webapp-2 / main |
| 운영 설정 | deployment/wrangler.jsonc |
| D1 / binding | webapp-2-goodmorning-production / DB |
| R2 / binding | webapp-2-goodmorning-media / R2 |
| 앱 스냅샷 | https://7543d6e6.webapp-2-9y5.pages.dev |
| 복구 자료 | 별도 기술 백업의 source/Git bundle·운영 SQL·verification.json |

루트 `wrangler.jsonc`는 로컬용입니다. 운영 배포는 **`npm run deploy`**가 `--cwd deployment` 설정을 사용합니다. 기존 다른 프로젝트 DB `webapp-production`을 재사용하거나 덮어쓰면 안 됩니다. 자세한 명령·DB UUID·개발환경·검사는 백업의 `webapp/README.md`에 있습니다.

## 백업의 의미와 한계

전달한 운영 SQL을 **독립 SQLite에 복원하여 게시물3개·CMS44개 일치를 검증**했습니다. 실제 운영 DB를 파괴적으로 초기화하는 복구훈련은 하지 않았습니다. 백업은 생성 시점 스냅샷으로 이후 수정·접수는 포함하지 않습니다. 전환 직전에 최신 백업을 다시 확보해야 합니다.

현재 배포 검증 때 실제 보존할 R2 콘텐츠는0건이었고 시험 이미지는 삭제했습니다. 향후 업로드가 생기면 **DB만으로 파일을 복구할 수 없으므로 R2 객체/키/메타데이터도 함께 백업**해야 합니다. 정기 자동 백업은 설정되어 있지 않습니다. 보관위치·주기·복구 담당자는 인수 시 확정합니다.

## 접근정보와 유지보수

관리자 비밀번호는 별도 파일로 안전하게 전달합니다. 일반 자료나 공개 게시판에 올리지 않습니다. Cloudflare 계정의 소유권을 강도욱 원장님 측으로 이전한 상태는 아니며, 접근권한과 비용/유지보수 담당자를 별도로 합의해야 합니다. 무상 유지보수 기간·SLA·대응시간·요금은 이 문서로 임의 확정하지 않습니다.

오류 전달 시 **페이지 주소, 발생 시간, 기기/브라우저, 재현 순서, 기대 결과, 화면 캡처**를 남깁니다. 비밀번호·환자 개인정보·지원자 연락처는 캡처에서 가립니다.
